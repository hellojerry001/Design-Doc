# 适配器 · 接口

接口页的骨架是固定的，适配工作主要是**把接口清单弄出来**。

```
# 接口名
> 版本 ｜ 调用方 ｜ 权限要求
## 功能描述
## 参数          ← 表格：参数 / 类型 / 必填 / 说明
## 返回值        ← 表格：字段 / 类型 / 说明
## 调用示例
## 实现位置      ← 文件:行号 + 最小实现片段
## 注意事项
## 相关接口
```

> **把「实现位置」写进骨架**是这套模板里最值钱的一条：读者能一路点到源码，
> 文档就不需要重复解释实现细节了。

---

## 怎么弄到接口清单

### Tauri 命令 / 装饰器注册

用 `grep` 抽声明行即可：

```bash
grep -rn "#\[tauri::command\]" src-tauri/src | wc -l
```

再从每个命令的函数签名里抽参数与返回类型。文件名即页面名（`pick_directory.md` ↔ `pick_directory`）。

### Express / Fastify / Koa 路由

抽路由注册行：

```bash
grep -rnE "router\.(get|post|put|delete)\(" src
```

### OpenAPI / Swagger

直接读 `openapi.json` 生成页面。这种最省事 —— 字段类型、必填、示例都是现成的。

### 前端调用方（最准的清单）

如果后端没有统一的注册表，**从前端调用处反查**反而最准：

```bash
grep -rnE "invoke\(|fetch\('/" src chrome-extension
```

这能同时告诉你「谁在调用」，正好填进「调用方」那一栏。

## 分组建议

按**调用方**分，不要按 HTTP 方法或文件目录分：

| 好的分组 | 差的分组 |
|---|---|
| 主应用命令 / 浮层命令 / 定时任务 | GET 接口 / POST 接口 |
| 审计相关 / 附件相关 / 会话相关 | utils.ts 里的 / api.ts 里的 |

理由：读者是带着「我在做哪个功能」来的，不是带着「我要找个 POST」来的。

## 维护成本

接口是最容易漂的一类文档 —— 加接口的人通常不会顺手写文档。

两个降低成本的措施：

1. **留一份 `_template.md` 在导航里**（不要藏起来）。新接口直接抄，比翻规范快得多。
2. **生成而非手写**。有 OpenAPI 就用 OpenAPI；没有的话，`scan-project.mjs` 抽出的清单至少要能告诉你「源码里有 34 个命令，文档里有 30 页」——**这个差值就是漂移量**，能报出来就有人会补。

> 前端侧真值可以从 `package.json` 的版本号 + 命令总数两个数字对上验证。
> 数字对不上时，多半是有人加了接口没写文档 —— 这正是文档站该暴露的信号。
