# 验收清单

每个阶段的**门槛**。不达标就不要进下一步 —— 尤其是 Phase 1，跳过它会返工。

## Phase 0 · 勘察

- [ ] 资产清单里每一类的数量都数出来了，且**用两套独立实现互验**
- [ ] 每类资产都标了命中「源码」还是「快照」
- [ ] 给出了「建议开哪几个板块 + 理由」，而不是只丢一份清单

## Phase 1 · 定 IA（**强制卡点**）

- [ ] 导航树完整：板块 → 分类 → 条目 → 锚点
- [ ] 每个资产都有归属，**没有「其他」这种垃圾桶分类**
- [ ] 用户已确认

## Phase 2 · 立骨架

- [ ] `npm run docs:dev` 起得来
- [ ] `npm run docs:build` 通过（这一条同时覆盖 SSR 安全 + 死链）
- [ ] 侧边栏结构与 `IA.md` 一致

## Phase 3 · 逐条填

- [ ] 每个条目要么有实时预览，要么明确写了「为什么没有预览」
- [ ] 组件页 / 接口页的标题层级与模板**逐字一致**（骨架一致性是能长大的前提）
- [ ] 凡是快照数据，页头都有来源标注与同步时间

## Phase 4 · 校验（硬数字，不接受"看起来没问题"）

| 断言 | 期望 |
|---|---|
| `.NotFound` 元素数 | 0 |
| 每页 h1 | 与预期标题一致 |
| 条目数 | **等于**预期总数（不是"大于 0"）—— 只判断 h1 存在会漏掉"少了一整组数据" |
| 侧边栏二级项数 | 等于 `gallery.config` / 分类表的项数 |
| 每个分类锚点 | 逐个跳一遍，落点 `-80 < top < 520` |
| 文本截断 | `scrollWidth > clientWidth + 1` 的元素数 = 0 |
| 横向溢出 | `document.documentElement.scrollWidth === window.innerWidth` |
| 每个可视化 kind | 逐个数渲染出的元素，**任一为 0 视为死分支**，且要**逐档作用域分别数** |
| 交互 | 页签切换 / 搜索 / 变体切换 / 复制，逐个点一遍；复制用 `navigator.clipboard.readText()` 回读 |
| 主题 | 亮色 + 暗色各截一张图，确认预览确实跟随 |
| 控制台 | 无 pageerror；`response` 里无 ≥400（favicon 除外） |
| 快照标注 | 构造一份缺 `syncedAt` 的快照，确认**构建失败**（不能静默通过） |

## 交付

- [ ] 验收截图归档，且**给人看过**（不是只跑了脚本）
- [ ] 至少在一个**形态不同**的项目上跑过全流程（同形态的项目验证不出泛化能力）
